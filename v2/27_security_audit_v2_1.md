# 27. Security audit v2.1.0: Secret Shopper vault contract

Date: 2026-11-03. Scope: `contracts/shop/src/lib.rs` 2.1.0 (wasm `target/near/secret_shopper.wasm` as built), focus on the six changes since v2/25, plus `scripts/global-vault.ts` and `scripts/verify-evidence.ts` where they carry a contract claim. Method: line review against NEAR runtime semantics (FC key gas and allowance, storage staking, CreateAccount receipts, NEP-591, NEP-616) and near-sdk 5.29.1 `store` internals; four sandbox proofs in `contracts/shop/tests/audit_v21.rs` (all pass, 101 s).

Result: no High or Critical. One Medium (evidence of a vault's history is not bound to the vault), three Low, two Info.

## 2. Change-by-change notes

1. **Rolling new-payee limit.** Sound. Walked both orders of equal `(at, amount)` marks for a new and a known payee in one block: removal or zeroing is interchangeable and keeps both the cap total and the new-payee count right. `paid` is set at transfer time, so a payee counts as new exactly once whether its first transfer worked or not. A failed first payment now also keeps a `max_payments_per_day` slot for 24 h (stricter than 2.0.0, fine). Intents rail uses the same flag; V2-14 (partial use refunds the full amount to the cap) is still open.
2. **assert_float.** V21-01, V21-02, V21-05. The agent cannot block `commit_batch` while it can still pay: both use the same reserve, the agent's prepaid gas makes its own check stricter, and the band where commit fails but pay works (immediate `commitments` writes, 109 B per slot) is a few mNEAR, worth at most one pay.
3. **Misdirected.** No avoidance path found. The `touched` branch (`lib.rs:1044`) runs before the Misdirected branch, so paying the lure payee under any invoice, before or after declining or misdirecting the lure invoice, is `Failed` (`v21_misdirected_does_not_shield_lure_payee`). The agent cannot force `Invalid` (needs owner approval or a preimage). Misdirected needs expiry and still marks the lure payee and invoice as scored.
4. **set_limits.** Correct. Invariant: the queued target is field-wise at least the live limits (mixed calls apply the minimum first; any pure tightening clears the queue), so `apply_limits` never undoes a later tightening.
5. **Parent init.** V21-03, V21-04. Stranger init and re-init are refused (PoC). Top-level, implicit and eth-implicit ids have no parent. Only the direct parent can create a sub-account, and after the creation receipt the parent has no actor rights on it, so the atomic flow has no front-run window.
6. **Ciphertexts.** Header pins round and quicknet hash, sha256 pins bytes, args only so no storage. It cannot prove the body decrypts (junk body or an extra stanza for a later round); `verify-evidence` check 4 shows that as sabotage at the round.

## 3. Checked and fine

| Area | Result |
|:-|:-|
| Phantom events | The drained reveal in V21-01 logged `test_revealed` and `agent_demoted` inside a receipt that rolled back. `backend/src/lib/near/events.ts:106` drops non-success receipts. Third-party indexers must do the same (V2-13 family) |
| Registrar parents | near-linkdrop `create_account_advanced` can deploy code or attach a global contract but makes no function calls, so it cannot init a vault |
| Demotion under drain | If the demote receipt itself lacked balance, `DeleteKey` and `AddKey` revert together; authority is still cut by `mode` (`lib.rs:1511`), only `propose` becomes unusable |
| `armed_at` with `>=` | A decision in the same block as freeze plus re-arm of the same key would count against the new arming; needs three owner and vendor txs in one block, negligible |
| Callbacks | `on_paid*` stay outside both FC method lists; `#[private]` holds |
| Late lure payment | A payment to the lure payee after `expires_at` is `Unanswered` by design (SS-C04, V2-02); still open as documented |
